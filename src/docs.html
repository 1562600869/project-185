.skip-link 无障碍使用文档

本文档描述 .skip-link 组件的无障碍实现细节，涵盖其定位方式、聚焦可见性策略以及 href 目标指向的规范要求。

一、概述

Skip link（跳转链接）是一种面向键盘用户和屏幕阅读器用户的无障碍辅助机制。 它允许用户跳过页面顶部的重复性导航内容，直接到达主内容区域。 WCAG 2.4.1 Bypass Blocks 明确要求页面提供跳过重复块的机制。

适用场景：所有包含全局导航栏、页眉、面包屑等重复内容的页面，均应在 <body> 的第一个子元素位置放置 skip link。

二、HTML 结构

<!-- skip-link 必须是 body 的第一个子元素 -->
<body>
  <a class="skip-link"
     href="#main-content">
    跳转到主要内容
  </a>

  <header><!-- 导航等重复内容 --></header>

  <main id="main-content" tabindex="-1">
    <!-- 主要内容 -->
  </main>
</body>

关键属性说明

属性值说明
class "skip-link" 绑定 CSS 样式，控制定位与聚焦可见性
href "#main-content" 指向主内容容器的 id，点击后页面滚动至目标区域
tabindex（目标元素） "-1" 使 <main> 等非交互元素可通过脚本聚焦，确保跳转后焦点正确落位

三、定位方式

.skip-link 采用 position: fixed 定位策略，始终固定在视口左上角， 默认状态下通过 transform 将其移出可视区域，实现"视觉隐藏但屏幕阅读器可读"的效果。 

.skip-link {
  position: fixed;
  top: 8px;
  left: 8px;
  z-index: 10000;

  /* 默认隐藏：向上移出视口 */
  transform: translateY(-200%);

  transition: transform 0.15s ease-in-out;
}

定位策略对比

方案优点缺点是否推荐
position: fixed + transform 不占文档流空间；动画平滑；不依赖 overflow 裁剪 需要 z-index 管理 ✅ 推荐
position: absolute + left: -9999px 实现简单 部分屏幕阅读器会朗读偏移后的位置信息；回归动画不平滑 ❌ 不推荐
display: none / visibility: hidden — 从可访问树中完全移除，屏幕阅读器无法读取 ❌ 禁止使用
clip-path: inset(50%) 现代浏览器支持好 旧浏览器兼容性差 ⚠️ 可选
为什么选择 position: fixed？
使用 fixed 定位确保 skip-link 不随页面滚动位移，无论用户滚动到何处，激活时始终出现在视口左上角的固定位置，提供一致的可预期体验。配合 z-index: 10000 保证其在所有页面层级之上可见。

四、聚焦可见性

聚焦可见性是 skip-link 无障碍体验的核心。组件必须在键盘用户按下 Tab 时变得可见， 同时对鼠标用户保持隐藏，避免干扰视觉设计。

4.1 焦点触发显示

.skip-link:focus {
  /* 滑入视口，变得可见 */
  transform: translateY(0);

  /* 高对比度焦点轮廓 */
  outline: 3px solid #ffbf47;
  outline-offset: 2px;
}

4.2 区分键盘与鼠标焦点

/* 现代浏览器：仅在键盘聚焦时显示 */
.skip-link:focus-visible {
  transform: translateY(0);
  outline: 3px solid #ffbf47;
  outline-offset: 2px;
}

/* 鼠标点击时保持隐藏 */
.skip-link:focus:not(:focus-visible) {
  transform: translateY(-200%);
  outline: none;
}

4.3 可见性要求清单

  • 对比度：skip-link 文字与背景色的对比度需 ≥ 4.5:1（WCAG AA 级）。当前方案白色文字 (#fff) 在蓝色背景 (#005fcc) 上对比度约为 5.6:1。 WCAG 1.4.3
  • 焦点指示器：焦点轮廓使用高对比度黄色 (#ffbf47)，宽度 3px，与组件自身蓝色形成鲜明对比，确保在各类背景下均可见。 WCAG 2.4.7
  • 字号：不小于 16px，避免在高分辨率屏幕上过小。 WCAG 1.4.4
  • 动画时长：过渡动画控制在 150ms 以内，既提供平滑视觉反馈，又不影响操作效率。 WCAG 2.3.1
禁止使用 outline: none 移除焦点轮廓！
移除默认焦点轮廓而不提供替代方案会导致键盘用户完全无法看到当前聚焦元素， 严重违反 WCAG 2.4.7（Focus Visible）要求。

五、href 目标指向

skip-link 的 href 属性是一个页内锚点链接，指向主内容容器的 id。 正确设置目标指向是确保跳转功能生效的前提。

5.1 目标元素要求

<!-- 目标元素必须设置 id 和 tabindex -->
<main id="main-content" tabindex="-1">
  <!-- 页面主要内容 -->
</main>
属性必须说明
id ✅ 唯一标识符，与 skip-link 的 href 值对应（含 # 前缀）
tabindex="-1" ✅ 使 <main>、<div> 等非交互元素可接收程序化焦点。-1 表示不进入 Tab 序列，但可通过 .focus() 或锚点跳转聚焦

5.2 目标元素的 CSS 配合

/* 平滑滚动至目标时留出顶部间距 */
#main-content {
  scroll-margin-top: 20px;
}

/* 目标聚焦时的视觉反馈 */
#main-content:focus {
  outline: 3px solid #005fcc;
  outline-offset: 4px;
}
  • scroll-margin-top：当页面使用锚点跳转滚动至目标时，在目标顶部留出间距，避免内容紧贴视口边缘。
  • :focus 轮廓：跳转完成后，目标元素显示焦点轮廓，帮助用户确认当前所处位置。

5.3 多个 Skip Link 的场景

对于结构复杂的页面，可以提供多个 skip link，分别指向不同区域： 

<nav aria-label="跳过链接">
  <a class="skip-link" href="#main-content">跳转到主要内容</a>
  <a class="skip-link" href="#search">跳转到搜索</a>
  <a class="skip-link" href="#footer-nav">跳转到页脚导航</a>
</nav>
href 目标常见错误：
  • ❌ href="#" — 回到页面顶部，无实际跳转效果
  • ❌ href="javascript:void(0)" — 非锚点链接，屏幕阅读器无法正确解读
  • ❌ 目标元素缺少 tabindex="-1" — 部分浏览器中焦点不会跟随跳转
  • ❌ href 与目标 id 拼写不一致 — 跳转完全失效

八、测试方法

8.1 键盘测试

  • 打开页面后，按 Tab 键 — skip-link 应出现在视口左上角
  • 按 Enter 键 — 页面应滚动至主内容区域，焦点落在 #main-content 元素上
  • 继续按 Tab 键 — 焦点应从主内容区域内的第一个可交互元素开始，不回到页面顶部

8.2 屏幕阅读器测试

  • 使用 NVDA / JAWS / VoiceOver 打开页面
  • 屏幕阅读器应朗读 "跳转到主要内容，链接"
  • 激活链接后，应朗读主内容区域的起始内容

8.3 自动化测试

  • 使用 axe-core 扫描页面，确认无 "bypass blocks" 相关违规
  • 使用 Lighthouse 无障碍审计，确认 skip-link 相关项通过
